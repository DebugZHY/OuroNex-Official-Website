Specialist domains

One layer, four kinds of engineering depth

Generic AI tools lack engineering grounding; point solutions cover only one task. SIDA is designed to coordinate role-specialized capability across the disciplines a structural practice actually runs.

Analysis & design

Analysis support is scoped around established numerical methods and specialist calculation tools, not generic model output. The design intent: assumptions stay explicit, intermediate steps stay visible, and results arrive in a form a reviewer can interrogate.

BIM coordination

BIM support is scoped to model-related workflows and coordination, designed to connect with the tools firms already use rather than replace them. Models are treated as shared engineering context, so information flows between analysis, documentation, and review.

Codes & specifications

Code support is a scoped requirement: work is to be checked against codes and specifications using domain knowledge bases, with updates tracked as standards evolve. References must stay traceable, so an engineer can see which provision drives a result.

Documentation

Documentation support is scoped to keep sketches, calculations, and project records consistent as work evolves. Because it draws on the same context as analysis and review, deliverables should stay aligned with the decisions behind them, with an audit trail retained.

Research core

SODA — Second‑Order Direct Analysis

At the centre of SIDA's analysis capability sits SODA: a core analysis and design module that translates our team's structural engineering research in second-order direct analysis into working software.

Research-driven means building on established numerical methods and specialist calculation tools — with explicit assumptions and engineering review — rather than a general model's approximation. The module is designed to embed in SIDA and extend for customized developments, so client-specific methods can join the same reviewed workflow.

Design principles

Trust is an architectural decision

01

Engineers stay in command

AI assists; qualified engineers verify and make the final call. Human-in-the-loop review and staged acceptance are designed into the workflow, not appended to it.

02

Designed for audit

Explainability and audit trails are design priorities: a reviewer should be able to trace how an output was produced — which knowledge, which tools, which steps — before anything reaches a project.

03

Your data, your governance

Private deployment options, role-based access controls, encryption, and clear data governance are scoped requirements for protecting client data and intellectual property.

04

Reliability under coordination

A modular agent architecture, explicit orchestration protocols, and an evaluation harness set the requirement that multi-agent behaviour stays testable and output quality measurable.
